# Automatic chapter editing

Every newly generated chapter, continuation and pending-section rewrite is checked after Astra and all AION insertions finish, before the background job can report its draft ready. Completing a legacy or manually changed draft also passes through this stage. Existing saved manuscripts are not automatically rewritten. The separate manuscript editor, selected-passage rewrite interface and model selections are unchanged.

## Processing

1. Build paragraph-addressed current prose and bounded, identified samples from actual earlier chapters: openings, endings, aftermaths, recurring small actions, recurring wording and source-grounded resolved conversations. Exclude replacement/future chapters. A stale memory quote is not evidence. Samples are explicitly labelled selective, not a claim to review the full previous manuscript.
2. Local checks propose possible clause chains, repeated opening/aftermath structures, gestures, dialogue mechanisms and exact repeated paragraphs. Signals are not word bans. GPT-5.4 mini (pinned `gpt-5.4-mini-2026-03-17`) assesses them and the complete current chapter, returning a structured, source-quoted report. Every signal must be accounted for. Known paragraph references are sorted/deduplicated, shared findings are combined into one replacement per paragraph, and disjoint addresses do not include intervening text. Unsupported source IDs/evidence and incomplete findings still fail the check. Invalid reports are retained against exact source/context for validation after a code correction without purchasing the same analysis again.

Evidence has no arbitrary character minimum: an exact short reply such as “Eight.” is valid. Quote/apostrophe typography and whitespace can be normalised for comparison, but actual words must still match the named source. The schema restricts paragraph/source/signal/change IDs to the IDs actually supplied. No candidate signals means an empty assessment array. Unsolicited category labels in older retained reports are ignored; missing actual candidate assessments are still rejected. Different visits, logistics or purposeful physical actions are not automatically repetition merely because they share a subject.
3. If needed, one bounded batch per original writer repairs only the identified passages. Actual writer provenance is retained across insertions; AION-origin passages stay with AION. For legacy drafts without provenance, explicit vocabulary routes to AION. This fallback is imperfect and is not presented as proof of who wrote old prose. Each batch is a separately checkpointed call.
4. Exact-range application changes only the original targets. A length floor rejects obvious summaries. Mini checks the complete candidate and every before/after pair for preserved events, actions, substantial interiority, voices, physical detail, heat and endpoint, as well as remaining/new repetition. Similar length alone does not establish preservation.
5. Only a valid pass commits the candidate. The receipt is bound to draft text, prior chapter hashes, Bible, guidance, relevant state and author style context. Completing an unchanged checked draft does not purchase the same check again. Manual changes invalidate the receipt. Prior originals/replacements are retained as bounded, reversible edits in the receipt; `restoreEditorialOriginal` refuses newer edited text. Automatic edits are not submitted as author corrections for preference learning.

## Author changes take priority

Manual draft saves, reader-selected rewrites and undo mark their changed paragraphs as author-owned. Those current paragraphs remain verbatim during automatic editing. Their offsets and source text are verified; replacements cannot intersect them, and a final check rejects any candidate losing a protected passage. Unchanged surrounding paragraphs can still receive automatic fixes. A deletion protects its new join rather than retaining deleted wording. Continuation carries existing protection forward without marking new machine prose as a human edit.

Older installed clients are supported at authenticated job submission: compare their current draft with owner/story-scoped saved writer output for the same chapter metadata. Never use a previous author input as the baseline. If no trustworthy writer baseline remains, protect the current draft conservatively instead of guessing. No paid model is used for this comparison, and no manuscript is changed by discovering the protected paragraphs. These markers are editorial ownership metadata, not content restrictions or new approval steps.

## Limits and cost

- No per-finding approval or spoiler report is shown during generation. Existing background status reports checking, correcting and rechecking. Existing generation diagnostics identify each model/call and cost.
- Additional editing request reservations total at most **US$0.25 per chapter job**, or a lower positive `NOVELFORGE_AUTO_EDIT_MAX_USD` server setting. This is additional to normal planning/writing/continuity costs. Reservation uses conservative UTF-8 byte token bounds plus framing/schema allowance, output limits and published standard prices. It assumes neither caching nor complimentary traffic. Mini uses no hidden reasoning; writers use low reasoning within the same output cap. Complimentary billing must be verified separately in the provider account.
- At most one initial check, one repair batch per writer (maximum two), and one recheck. No SDK retries, fallback providers, second repair loop or replay of an ambiguous in-flight stage. A cost rejection happens before the next submission. Reported costs above a reserved estimate stop further requests; provider billing/pricing cannot be controlled by application code.
- Repair directions are deduplicated across their source targets, with complete target text and short neighbouring context. Reserve the conservative ceiling before each call, then release unused reservation only when provider usage supplies a known cost estimate/report. Missing usage retains the full reservation; free-token eligibility is never assumed. The extra request budget remains US$0.25.
- Up to eight evidenced findings, at most eight known paragraph references per finding, targets grouped into at most three consecutive paragraphs of the same writer, 1,000 original words per writer batch, 100,000 chapter characters. Excess issues/size, an interrupted or malformed response, a cost limit, lost detail or unresolved repetition preserves the original draft and reports a stopped job, not a false ready result. No extra paid request starts automatically.
- These are enforceable processing and validation requirements. Editorial judgement is still model-based: no claim of perfect prose, complete recall of every prior passage or guaranteed detection of all repetition.

## Verification

`scripts/test-automatic-prose-editorial.cjs` covers pure evidence/target checks, negative cases, provenance, exact reversible patches, stale receipts, budgeting and mocked provider requests. `scripts/test-chapter-background.cjs` exercises the complete checkpointed workflow for both writers, pre-ready enforcement, automatic repair/recheck, preservation failure, unresolved findings, stopped providers, no paid replay and reuse of a checked draft. These tests make no live provider or database calls; they verify mechanics, not a live model's editorial sensitivity.
